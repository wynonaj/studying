Layering|A browser can keep requesting pages after you switch from Ethernet to Wi-Fi because the lower-layer delivery details can change without changing the web request format.|Think of dividing a group project into jobs: each person can improve their part without rewriting everyone else's work.
Protocol|Two devices must agree on message format and meaning. If one sends a request the other cannot interpret, a working cable alone cannot make them communicate.|A shared language needs rules about what each message means and how to reply.
TCP/IP|TCP handles an ordered conversation between programs; IP handles packet addressing across networks. The suite also includes other protocols, so these two names label a larger family.|Split the name into two jobs: TCP handles the conversation; IP handles where packets go.
Application layer|HTTP gives a browser and web server rules for requests and replies. Those services are close to the program's purpose, while lower layers handle delivery.|Ask what the program wants to do, such as request a page, rather than how a cable carries it.
Transport layer|One computer may run a browser and a mail app together. Transport ports distinguish the application endpoints so incoming data reaches the appropriate conversation.|The destination computer is like a building; the port helps identify which office should receive the data.
Network layer|A destination can be several networks away. Routers read the destination IP address and choose a next hop, which explains why addressing and routing belong together here.|A local switch gets you across one local link; IP routing gets you toward another network.
Data Link layer|An IP packet needs a local wrapper to cross a particular link. Ethernet adds MAC addresses and an error check to form that wrapper, called a frame.|Think of the next delivery stop. The frame's local address can change when a router sends the packet onward.
Physical layer|A bit is an idea, not something a receiver can directly sense. The sender represents bits using voltage, light or radio so the receiver can measure them.|Copper carries electrical signals; fiber carries light; wireless uses radio.
OSI|A common seven-job reference helps people compare network designs and locate faults even when vendors build different products.|OSI is a map of responsibilities, not seven physical boxes inside a computer.
Presentation layer|A receiver needs to interpret a sender's representation of data. The OSI Presentation role covers format translation and concepts such as compression and encryption.|Changing how information is represented is different from choosing the route it travels.
Session layer|A continuing exchange needs a way to begin, coordinate and end the conversation. OSI names this conversation-management responsibility separately.|Think of opening and closing a meeting, rather than carrying each envelope to the meeting room.
Encapsulation|Each delivery layer adds its own control information: transport ports, then IP addresses, then local-link information. The previous unit becomes the next wrapper's contents.|Put the message inside labeled envelopes, one job at a time.
Decapsulation|The receiver processes the outer delivery information before passing the remaining contents upward. This lets the application receive its message without treating Ethernet labels as application data.|Open the outside envelope first, then the envelope inside it.
IEEE|IEEE's 802 standards families include wired Ethernet and wireless LAN rules. Shared specifications let interfaces made by different vendors use the same link technology.|Associate IEEE with the local connection: Ethernet and Wi-Fi.
IETF|Internet protocols must work across networks made by many organizations. IETF participants develop shared technical specifications through an open standards process.|Associate IETF with Internet conversations and delivery rules, such as TCP/IP and DNS.
LAN|A classroom's computers and printer can communicate through local switches without being a nationwide network. The limited geographic scope makes this a LAN.|Local describes the area covered, not a particular cable brand.
WLAN|Wi-Fi devices exchange local traffic through radio rather than requiring a cable to each device. The network is still local in scope.|The W adds wireless to LAN; it does not turn the network into a wide-area network.
TCP|TCP tracks sequence numbers and acknowledgments, retransmitting when necessary and presenting bytes in order to the receiving application.|A missing piece can be requested again; ordered delivery is a transport service, not something IP alone promises.
IP|IP packets carry source and destination addresses so routers can forward them toward another network. IP itself does not guarantee arrival or order.|An address helps find a route; it does not guarantee that the delivery succeeds.
DNS|People use readable names, while network software needs records such as an IP address. DNS queries obtain those records from a distributed naming system.|DNS is like looking up a contact's number before calling; it is not the call itself.
HTTP|A browser sends a request for a resource, and a server responds with a status and content. HTTP defines the meaning and format of that exchange.|Requesting a web page is an application job; forwarding its packets is a lower-layer job.
Interoperability|A computer and switch from different vendors can communicate when both implement compatible rules. Matching the shared specification matters more than matching the logo.|Different makers, compatible behavior.
Physical medium|A signal needs somewhere to travel. Copper, optical fiber and radio space provide different paths with different distance and interference limits.|Separate the path from the message: a cable is the medium; voltage changes are the signal.
Copper cable|Copper conductors allow electrical signal changes to travel between interfaces. Noise and signal loss affect how well the receiver can distinguish the changes.|Electrical signals use the metal; a fiber link uses light instead.
Fiber-optic cable|A transmitter launches light into fiber and a receiver detects it. Because information is carried optically, electromagnetic interference does not induce electrical noise in the glass.|Think light through glass, not electricity through copper.
Wireless|An antenna sends and receives electromagnetic signals through space. A cable is not needed between the radio endpoints, but interference and obstacles still affect reception.|No wire does not mean no physical signal: the radio wave is real.
UTP|Pairs of copper conductors are twisted to help reduce unwanted coupling and interference. Unshielded means there is no metallic cable shielding around those pairs.|Unshielded describes what is absent; twisted pair describes the two wires wound together.
EMI|A nearby electromagnetic source can disturb an electrical signal and make its intended values harder to detect. This is unwanted energy, not useful data.|A nearby electrical disturbance can act like background chatter while you are trying to listen.
Crosstalk|A signal in one nearby pair can couple into another pair. Twisting and proper cable construction help limit that unwanted interaction.|Cross-talk is one channel leaking into its neighbor.
Bandwidth|In signal math, bandwidth is a frequency range measured in hertz. In everyday network discussion the word may refer to data capacity, so the units tell you which meaning applies.|Hz measures frequency range; bits per second measures data rate. Check the units first.
Bit rate|Counting how many bits are transmitted each second gives a data rate. A symbol may represent more than one bit, so bit rate is not always symbol rate.|Bits per second counts information digits sent over time.
Gbps|The lower-case b means bits. Dividing a bit rate by eight gives a byte-rate equivalent before allowing for overhead and other limits.|Eight bits make one byte: 8 Gbps corresponds to 1 billion bytes per second before overhead.
Noise|Random unwanted changes can make one intended signal value look like another. A receiver needs enough separation between valid signal states to tell them apart.|Noise adds confusion; it is not the gradual weakening called attenuation.
Attenuation|Signals lose strength as they travel. If a signal becomes too weak relative to noise, the receiver may no longer distinguish the intended values.|A voice becoming quieter with distance is the memory aid for signal loss.
Cat 5e|The category specifies cable performance, while Ethernet standards determine supported links. A properly installed Cat 5e channel commonly supports gigabit Ethernet to 100 m.|Remember the pair of limits together: 1 Gbps and a 100 m channel for this common use.
Cat 6|Cat 6 supports gigabit Ethernet to 100 m, but 10-gigabit operation has shorter distance limits that depend on installation conditions.|A cable can support a faster speed only over a shorter distance; category alone is not the whole answer.
Cat 6a|The augmented category improves performance for 10GBASE-T over a full 100 m channel when properly installed.|The a is useful to associate with the full-distance 10-gigabit option.
Cat 8|Cat 8 uses shielding and supports short 25/40-gigabit copper channels up to 30 m. Calling it unshielded or assigning it the usual 100 m reach would miss its key limits.|Fast, shielded, short: keep speed, shielding and distance together.
Total internal reflection|At a suitable angle, light traveling in the higher-index core reflects at the lower-index cladding boundary instead of escaping. That helps guide it along the fiber.|The angle and the two materials matter; not every ray hitting any surface stays inside.
Core|In fiber, the central optical region guides the light. This is a material part of a cable, unrelated to the campus design tier also called Core.|First check context: fiber core carries light; campus core connects network regions.
Cladding|Cladding is the glass layer directly around an optical fiber’s core. The core is the center where the light signal is guided. The cladding has different optical properties that help keep that light guided along the core. Think of a boundary that helps light stay on its path—not a metal shield or the outer plastic jacket.|Core = light’s path; cladding = optical boundary around it; coating/jacket = physical protection.
Single-mode fiber|A small core supports one spatial propagation mode, avoiding the multiple-path spreading associated with multimode fiber. Suitable optics make long links possible.|One mode means less spreading from different paths, not an automatic fixed distance for every link.
Multimode fiber|Different modes can take different paths and arrival times, spreading a pulse. The larger core supports these modes, and the optics and fiber grade determine usable reach.|Multiple paths can blur pulses over distance; that is why reach is not unlimited.
Amplitude|Amplitude describes how far a signal moves from its reference level. Raising a wave's height changes amplitude without necessarily changing its cycles per second.|Height or strength is amplitude; how often it repeats is frequency.
Frequency|If a wave repeats more cycles each second, its frequency increases. Hertz means cycles per second, not bits per second.|Count repeats in one second, not how tall each wave is.
Phase|Two waves can have the same height and frequency but be shifted relative to each other. That relative position within the cycle is phase.|Imagine two equally fast runners at different positions on the same circular track.
Modulation|A carrier is varied in a controlled way so its states represent information. The receiver detects those changes to recover the encoded information.|The message tells the sender how to change the carrier.
AM|Information is represented by amplitude changes. Unwanted amplitude changes can therefore imitate part of the message and cause confusion.|For AM, watch the wave's height.
FM|Information is represented by changes in cycle rate. Amplitude disturbances are less directly confused with the encoded quantity, though performance depends on the system.|For FM, watch how closely the cycles are spaced.
PM|Information is represented by shifts in the carrier's phase relative to a reference. A phase shift differs from simply making the wave taller.|For PM, watch the position of the cycle compared with the reference.
QAM|Combining amplitude and phase creates multiple distinguishable symbol states. More states can carry more bits per symbol, but closer states require cleaner reception.|More choices per symbol give more information, but make neighboring choices easier for noise to confuse.
Multiplexing|Several streams share a resource by separating their use, such as into frequency bands or time slots. They do not each need a dedicated physical cable.|One road can serve several travelers if there is a rule for sharing it.
FDM|Separate frequency bands let streams occupy the same medium simultaneously. A receiver selects the appropriate band, like tuning a radio station.|Different frequency spaces at the same time.
TDM|Streams use assigned time intervals on the same resource. Taking turns separates them even when the same frequency range is reused.|Different turns on the same resource.
Ethernet|Ethernet defines wired link behavior including frames and MAC addressing. IP can be carried inside Ethernet, but Ethernet and IP solve different delivery jobs.|Ethernet handles the local link; IP handles network addressing beyond it.
Frame|A local-link receiver needs addressing and error-check information around the carried data. That header/payload/trailer unit is the frame.|An IP packet can be the contents of an Ethernet frame.
Packet|IP adds a network-layer header around the transport data. A link then carries this whole unit as its payload.|Packet is the IP wrapper; frame is the local-link wrapper outside it.
Payload|What counts as payload depends on which wrapper you are discussing. A full IP packet is Ethernet payload, including the IP header.|Ask: contents of which wrapper?
NIC|A host needs an interface that can transmit and receive using the link technology. The NIC provides that connection rather than choosing Internet routes for every remote network.|NIC is the computer's network doorway, not the entire network.
MAC|Media Access Control concerns local link access and addressing. An Ethernet MAC address identifies an interface for local frame delivery.|MAC tells the local frame where to go; IP serves the wider routed journey.
OUI|In a traditional universally assigned MAC address, the first three byte pairs identify an IEEE-assigned organization prefix. The remaining part is assigned within that block.|Three bytes × eight bits = 24 bits. Locally assigned MAC addresses need not identify a manufacturer.
Broadcast|One local message may need to reach everyone in a broadcast domain, for example during discovery. Routers normally stop Ethernet broadcasts from spreading into other networks.|Everyone locally is different from everyone on the Internet.
Unicast|The destination identifies one recipient rather than a group. A switch with a known destination mapping can choose that recipient's port.|One addressed recipient is unicast, even if an unknown-destination frame is temporarily flooded.
CSMA/CD|On shared half-duplex Ethernet, simultaneous starts can collide even after listening. Detecting a collision and waiting different random times lets devices retry.|Listen, send, detect collision, stop, wait randomly, retry. Full-duplex switched links do not use this collision procedure.
Collision|Two transmissions overlap on a shared half-duplex medium, preventing successful reception. Each sender must retry according to the access rules.|Both devices tried to speak over the same shared path at once.
Backoff|If both senders retried after the same delay, they could collide again. Randomized waits reduce the chance of synchronized retries.|Different waiting times help break the tie.
Full duplex|Separate sending and receiving paths allow both endpoints to transmit at once. This removes the shared-medium collision situation in switched Ethernet.|A two-way road with separate lanes allows simultaneous travel.
Half duplex|Both directions are supported, but the shared resource cannot carry both transmissions simultaneously without conflict.|A walkie-talkie can talk both ways, but users take turns.
Preamble|A known alternating pattern helps the receiver synchronize before the frame begins. It is not a destination address or application payload.|Get the receiver ready first; then mark where the actual frame starts.
SFD|After synchronization, a distinct one-byte pattern marks the start boundary so the receiver knows where frame fields begin.|Preamble prepares; delimiter marks the boundary.
Destination MAC|A switch uses the destination field to decide where a frame should go on the local network. Across a router, a new link frame uses the next local destination.|Destination answers who receives this local frame, not who originally created the application message.
Source MAC|Switches learn which MAC addresses are reachable through incoming ports by examining the source field.|Source tells who sent this frame; destination tells where it should go.
EtherType|The receiver must know how to interpret the payload. EtherType says which protocol, such as IPv4 or IPv6, follows the Ethernet header.|This label says what is inside the envelope.
Padding|A short payload needs extra bytes so the Ethernet frame reaches its minimum size. Padding does not turn into additional meaningful application data.|Fill unused space to reach the minimum frame length.
FCS|The sender computes a check value over the frame and includes it at the end. A receiver compares its own calculation to detect corruption.|A mismatch signals damage; the check itself does not repair the data.
CRC|CRC is the calculation that produces a check value. FCS is the field carrying that value in an Ethernet frame.|Calculation versus container: CRC computes it; FCS carries it.
MTU|An Ethernet IP MTU of 1500 counts the carried network-layer packet. Adding the Ethernet header and FCS makes a larger frame.|1500 is commonly the IP packet limit, not the entire 1518-byte untagged Ethernet frame.
Bit|One binary position has two possible values, so each additional bit doubles the number of possible combinations.|One switch has two states; two switches have four combinations.
Byte|Grouping eight binary digits creates 2⁸ = 256 possible patterns. Network sizes in bytes therefore differ by a factor of eight from sizes in bits.|Eight bits fit in one byte; do not confuse b with B.
Octet|The word explicitly means eight bits. Each dotted decimal IPv4 part represents one such eight-bit group.|An IPv4 part can display 0 or 255 and still occupy the same eight bit positions.
Nibble|Four bits have 16 possible patterns, matching exactly the 16 hexadecimal digit values.|One hex digit is one nibble; two hex digits make a byte.
Binary|The position values double as you move left: 1, 2, 4, 8. Add only the values whose digit is 1.|1010 means 8 + 2, not the decimal number one thousand ten.
Decimal|Each position is ten times the one on its right. For example, 42 means four tens and two ones.|The familiar counting system is only one way to write a quantity.
Hexadecimal|Each position is sixteen times the one on its right. A through F provide single symbols for values 10 through 15.|Hex 2A means two sixteens plus ten: 32 + 10 = 42.
Hub|A hub repeats a received signal without reading a learned destination table. Connected half-duplex devices share the same collision domain.|A hub repeats; it does not choose a port by looking up a MAC address.
Switch|A switch learns from source MAC addresses and looks up destination MAC addresses when forwarding. Unknown unicast and broadcasts are flooded within their VLAN.|Learn from source, forward by destination.
STP|Extra switch links provide alternatives but can also form forwarding loops. STP blocks selected paths so active forwarding remains loop-free.|Keep backup roads available without letting a frame circle forever.
Topology|A topology shows how devices and connections are arranged. Physical wiring and the logical flow of traffic may have different shapes.|Look at which nodes connect, not merely where icons are drawn on the page.
Star topology|Each endpoint has its own link to a central device. That central connection pattern is the identifying feature.|Spokes meet at one center.
Bus topology|Multiple devices share a common main path. The shared backbone, rather than a separate center-to-endpoint link for each device, identifies a bus.|Several stops along one shared line.
Ring topology|Each part connects along a loop that returns to its starting point. The circular connection structure identifies the ring.|Follow the links and you come back around.
Mesh topology|Multiple interconnections create alternative paths. In a full mesh, every pair is directly connected; a partial mesh has fewer links.|Several ways through, not just one center or one line.
VLAN|A switch can separate ports into logical broadcast domains. Frames in one VLAN do not simply become local broadcasts in every other VLAN.|One physical switch can host several separate logical local networks.
Router|A router uses destination IP prefixes and forwarding information to move packets between networks. A basic Layer-2 switch instead forwards local frames by MAC address.|Use a router when the packet must leave its local IP network.
Routing|A forwarding decision chooses the next step toward a destination. Each router makes its own decision using its available routes.|You do not have to know every street to choose the next useful turn.
Routing table|Entries associate destination prefixes with an outgoing interface or next hop. A router matches the packet's destination against these entries.|It is a list of where to send traffic for address ranges, not a complete drawing of every device.
Next hop|A packet may need several routers to reach its final destination. The next hop is just the immediately following forwarding stop.|Next stop and final destination are not necessarily the same place.
IPv4|Four groups of eight bits give 32 bits total. Decimal dots make the groups easier to read, but routers work with the bit values.|Four octets × eight bits; a slash prefix says how those bits are divided.
IPv6|Eight groups of sixteen bits give 128 bits. Hexadecimal provides a compact representation, and zero compression can shorten it further.|Colons separate groups; each full group has four hex digits, not four bits.
Network portion|The prefix identifies the subnet shared by its members. Two interfaces in that subnet can share those bits while differing in the remaining positions.|The common street portion of the address is the memory aid.
Host portion|The bits after the prefix can vary within the subnet. Their patterns create address choices, although ordinary IPv4 subnets reserve the all-zero and all-one patterns.|Host bits are positions; host addresses are the values formed from those positions.
CIDR|A variable prefix length lets the address block size match needs more closely than the old fixed classes. The slash number counts network bits.|A larger IPv4 prefix leaves fewer host bits and therefore a smaller block.
Prefix length|IPv4 contains 32 positions. Reserving 17 for the network leaves 15 for the host portion, so /17 is not a count of hosts.|Subtract the slash number from 32 before counting addresses.
Subnet mask|Mask ones select the network portion and mask zeros identify the host portion. A /24 mask has 24 ones followed by eight zeros.|The mask marks positions; it is not the destination device's address.
Network address|Setting all host bits to zero gives the first address of an ordinary subnet. That value names the subnet rather than an individual host.|For 192.168.5.34/24, keep the first three octets and zero the last: 192.168.5.0.
Broadcast address|Setting all host bits to one gives the final address of an ordinary IPv4 subnet. It is reserved for reaching the subnet rather than assigning it to one interface.|For /24, the final eight bits become 11111111, which is 255. /31 point-to-point and /32 have special rules.
Classful addressing|Fixed class sizes can force an organization to accept far more addresses than needed. CIDR varies the prefix instead of forcing those fixed sizes.|A choice of only a few huge box sizes wastes space; variable prefixes allow a closer fit.
Hextet|Four hexadecimal digits each represent four bits, so one full IPv6 group represents sixteen bits. Omitted leading zeros do not change its width.|The displayed group 1 means 0001 in a full four-digit group: still 16 bits.
Zero compression|The receiver counts the written groups and fills the remaining positions with zeros. Two separate double colons would not say how to divide the missing groups.|One missing stretch can be reconstructed; two stretches would be ambiguous.
ICMP|IP delivery needs a way to report conditions such as an unreachable destination or an expired hop limit. ICMP carries that control information.|A delivery problem report is different from the application's normal message.
Ping|Echo requests ask an endpoint to send an echo reply. The elapsed time measures a round trip, but filtering can block replies even when a device exists.|No reply is a clue, not proof that the computer is switched off.
Traceroute|Probes with gradually increasing TTL or hop limits expire at progressively later routers. Replies can reveal those forwarding stops.|Ask one step away, then two, then three; a silent router may still forward traffic.
Pathping|It first discovers a route and then gathers probe statistics over time. That gives more loss and delay information than one simple reachability check.|Think path discovery plus repeated measurements, while remembering routers can limit probe replies.
TTL|Each router reduces the IPv4 TTL; a packet is discarded when it expires. This prevents a routing loop from keeping the packet alive indefinitely.|Despite the name Time To Live, normal forwarding treats it as a hop budget.
Latency|Latency measures waiting time for data to travel. A link can have a high data rate and still have a long delay because the destination is far away.|Road width is like capacity; travel time is like latency.
Packet loss|Some transmitted packets never arrive, for example because of congestion or corruption. Loss is a missing delivery, unlike latency's delayed delivery.|Late and lost are different outcomes.
RIR|Public IP address blocks must be coordinated so unrelated networks are not assigned overlapping space. Regional registries manage that allocation and registration within their regions.|Allocation means assigning a block. Think of keeping a regional address book so public addresses stay organized.
ARIN|ARIN is one of the regional organizations coordinating Internet number resources. Its service region includes the United States, Canada and parts of the Caribbean.|Identify it by its region and address-allocation job, not as a router inside a building.
RIPE NCC|RIPE NCC coordinates Internet number resources for its service region, including Europe, the Middle East and parts of Central Asia.|The organization administers address resources; it does not carry your packets along their route.
APNIC|APNIC performs the regional Internet-number registry role for the Asia-Pacific service region.|The Asia Pacific words help connect the abbreviation to its geographic responsibility.
LACNIC|LACNIC coordinates Internet number resources for Latin America and parts of the Caribbean.|This is a regional address-administration organization, not a networking protocol.
AFRINIC|AFRINIC serves the African region in coordinating Internet number resources. It is one member of the regional registry system.|The AFR part is the geographic memory cue; the job is address-resource coordination.
Requirements analysis|A design depends on who uses the network, which applications matter and what constraints exist. Buying equipment first can solve the wrong problem.|Find the need before choosing the hardware.
Logical design|Subnets, address plans and intended connectivity describe how the network should be organized without yet fixing every cable and device choice.|Draw who should communicate and how addresses are organized before choosing installation materials.
Physical design|The abstract connectivity plan must become actual equipment, media and placement. These installable choices form the physical design.|Logical is the organization plan; physical is what and where you install.
Building network|The scope is one building, even if it has many rooms, floors, switches or Wi-Fi access points.|Count the geographic scope rather than the number of devices.
Structured cabling|Predictable cabling paths, rooms and termination points make moves and repairs easier than a collection of improvised individual runs.|Organized wiring makes a fault easier to locate and a connection easier to change.
Horizontal cabling|Work-area outlets connect back to a local telecommunications room. Its role is serving those work areas, even if a cable bends or changes height.|Desk to local network room is the useful association; do not judge only by the cable's direction on a drawing.
Vertical cabling|Backbone cabling joins distribution spaces, floors or buildings. It links the local cabling areas rather than serving each desk directly.|Room-to-room backbone versus room-to-desk horizontal cabling.
Patch panel|Permanent cable runs terminate at labeled ports, allowing patch cords to connect them to equipment neatly. The panel itself does not route or switch packets.|A patch panel organizes connections; a switch actively forwards frames.
Telecommunications room|Cable terminations and local network equipment need an organized service location. Horizontal runs typically connect work areas back to this space.|It is the local wiring home base for the area it serves.
Data center|Servers, storage, networking, power and cooling are grouped to support applications reliably. It is a facility, not a numbered protocol layer.|Think of the place housing shared computing services and the infrastructure they need.
Data center topology|Server-to-server traffic needs capacity and alternate paths. The way leaf and spine switches interconnect affects those paths and resilience.|Topology is the connection plan inside the facility, not simply the floor plan.
Spine-leaf|Each leaf connects to every spine, allowing traffic between leaves through available spines. This creates predictable paths and alternatives if a path fails.|Servers attach to leaves; leaves reach spines. Do not substitute campus core/distribution/access tiers for this pattern.
Campus network|Nearby buildings are joined into one organized local environment, such as a university campus. The scope differs from one building or distant branch offices.|Several nearby buildings form the campus scope.
Core layer|In Chapter 12's campus design, distribution regions need fast, reliable connections to one another. The core supplies that backbone capacity.|Picture the main highways between neighborhoods, not the port where one student plugs in.
Distribution layer|Access networks need to be brought together and connected toward the backbone. This is a common location for routing between subnets and applying policy.|Gather neighborhood traffic and decide how it can move toward other areas.
Access layer|Computers, printers and access points need their first connection to the campus network. Access switches supply that edge connectivity.|Start at the user's device and follow its first network cable.
Backbone|Many smaller network areas depend on a main interconnection path. Carrying their combined traffic makes its capacity and reliability especially important.|The trunk connects branches; it is not each individual leaf's connection.
Enterprise network|An organization may join local networks across buildings and distant sites. Enterprise describes the organization's combined network, not one required topology.|One organization can have many connected local networks.
WAN|Distant local networks need broad-area connectivity, often through a provider. The geographic reach distinguishes WAN from LAN.|A connection between cities is a useful WAN example.
ISP|The provider connects customers to other networks and the Internet. It may also sell services linking an organization's distant sites.|The provider is an organization supplying connectivity, not a protocol inside a packet.
Firewall|Traffic is checked against configured rules and allowed or denied. Rules can distinguish permitted communication from unwanted access.|A controlled gate allows selected traffic; it does not automatically block everything.
Authentication|Before trusting an identity, a system checks evidence such as a password or credential. Permission to perform a particular action is a separate authorization decision.|Who are you comes before what are you allowed to do.
Network maintenance|Monitoring, testing, backups and updates help detect faults, recover from failures and keep the installed system useful.|Installation is the start; keeping it working is ongoing work.
Downtime|When a service is unavailable, people may be unable to work even though no new equipment is being purchased. That lost work is part of network cost.|A cheap design can become expensive if failures repeatedly stop work.
SNMP|Management software exchanges requests and notifications with agents on devices. This lets an administrator check values remotely instead of visiting every device.|Manager asks, device agent answers; notifications can report events without waiting for a poll.
MIB|Managed objects have defined names, types and meanings so management software can interpret device values consistently. Agents expose the actual values described by these definitions.|The MIB explains the dashboard gauges; the agent supplies their readings.
OID|A hierarchical numeric identifier names a managed object unambiguously. A manager can request a particular object rather than asking for an unnamed number.|Like a full path to one labeled gauge in a large tree of gauges.
Polling|A manager periodically asks for values so it can notice changes over time. This differs from a device sending an event notification on its own.|Polling asks are you okay repeatedly; a trap is the device announcing an event.
SNMP agent|Software on the managed device receives requests, accesses supported management values and returns results. An agent is not the administrator using the dashboard.|The agent is the device's local management helper program.
SNMP trap|An agent can send an event report without waiting for the manager to ask. A trap differs from a response to a periodic poll.|The device raises its hand when something happens.
Standard|Independent builders need an agreed specification for compatible behavior. Following the same rules helps their products exchange meaningful messages.|A shared recipe lets different builders make parts that work together.
Working group|People with technical expertise discuss proposals, resolve problems and develop specifications. In the IETF, decisions use rough consensus rather than simply counting votes.|These are people working on a shared technical document, not a group of computers with similar addresses.
